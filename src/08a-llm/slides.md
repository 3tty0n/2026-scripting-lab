## 言語モデルを4段階に分けて理解する

| 段階 | 問い | 主な道具 |
|---|---|---|
| 1. 表現する | 文字列をどうモデルへ渡すか | トークン、ID |
| 2. 予測する | モデルは何を返すか | スコア、softmax |

| 4. 会話にする | なぜ対話が続いて見えるか | テンプレート、履歴 |

- 各スライドの右側に、コードの読み方を書いてある

## 言語モデルとは
### 導入

- それまでの文字列から、**次に来るトークンを予測する**仕組み
- 返すのは文章ではなく、次の候補すべてへの「点数」
- 文章は、その予測を何度も繰り返してつなげて作る

> 巨大に見えても、外側のプログラムは「変換」と「ループ」でできている

## 第7回の「次の語を引く機械」を「会話」に発展させる
### 全体像

| | マルコフ連鎖 | 言語モデル |
|---|---|---|
| 次の候補 | `table[word]` | `next_scores(ids)` |
| 根拠 | 数えた回数 | 学習済みの重み |
| 見る範囲 | 直前1〜2語 | 直前の多くのトークン |
| 選び方 | 重み付き抽選 | greedy、温度、top-k |

予測器は大きくなるが「予測→選択→連結」のループは変わらない

## 言語モデルの出力: 次の候補すべてのスコア
### 2. 予測する

::: hstack wrap 3 2
```python
scores = next_scores(encode("日本の首都は"))

print(scores[:3])
# [(100562, 22.4), (3583, 20.9), (7814, 18.1)]
print(tok.decode([scores[0][0]]))
# '東京'
```
|||
**コードの読み方**

1. `next_scores(...)` は、次に来るトークンの候補を、`(ID, スコア)` の組のリストで返す
2. 高い順に並んでいるので、先頭 `scores[0]` が、もっともスコアの高い候補
3. `scores[0][0]` は、その ID。`tok.decode([...])` で文字列に戻すと「東京」
4. スコアは**確率ではない**。比べる前に、確率に直す
:::

---

## スコアは確率ではないので、softmax で確率に直す
### 2. 予測する — 課題1

::: hstack wrap 3 2
```python
import math

scores = [3.0, 1.0]
exps = [math.exp(s) for s in scores]
probs = [e / sum(exps) for e in exps]
print(probs)    # [0.88, 0.12]
```
|||
**コードの読み方**

1. `math.exp(s)`: スコアが大きいほど、より大きな正の数にする
2. `e / sum(exps)`: 全体の合計で割る。これで合計が 1 になり、確率として読める
3. スコア 3.0 は約 88%、1.0 は約 12%
- スコアが大きすぎると `math.exp` があふれるので、先に最大値を引く (確率は変わらない)
:::

> 課題1: `softmax(scores, temperature)` を書く

## 確率にすると、上位の候補を観察できる
### 2. 予測する

::: hstack wrap 3 2
```python
scores = next_scores(encode("日本の首都は"))
probs = softmax([s for _, s in scores])

for (token_id, _), prob in list(zip(scores, probs))[:5]:
    print(tok.decode([token_id]), prob)
```
|||
**コードの読み方**

1. `[s for _, s in scores]`: (ID, スコア) の組から、スコアだけを取り出す
2. `softmax(...)` で、確率のリストにする
3. `zip(scores, probs)`: 候補と確率を、同じ位置どうしで組にする
4. 先頭の 5 件について、トークンの文字列と確率を表示する
:::

> モデルは文章ではなく、まず「次の1トークンの分布」を返す

## greedy: 最大の候補だけを選ぶ方法
### 3. 選んでつなぐ

::: hstack wrap 3 2
```python
scores = next_scores(ids)
next_id = scores[0][0]
ids.append(next_id)
```
|||
**コードの読み方**

1. 今の ID のリスト `ids` を渡して、次の候補を得る
2. 先頭 (いちばんスコアの高い候補) の ID を、`next_id` にする
3. `ids` の末尾に足す
:::

1. 現在のID列をモデルへ渡す
2. 最大のスコアを持つIDを選ぶ
3. 選んだIDを末尾へ追加する
4. 終端IDが出るまで繰り返す

同じ入力なら毎回同じ結果になるため、動作確認に向いている

---

## greedyは局所的な最善を選ぶため単調になりやすい
### 3. 選んでつなぐ

```text
入力: 好きな食べ物は
出力: 好きな食べ物は何ですか？好きな食べ物は何ですか？...
```

- 各時点で1位の候補しか選ばない
- いったん反復へ入ると、同じ選択が続きやすい
- 文章全体としてよいかは、1トークン先の最大値だけでは決まらない

そこで、複数の候補を残し、確率に応じて1つを選ぶ

---

## 温度は候補間の差を、top-kは候補の数を変える
### 3. 選んでつなぐ

::: hstack wrap 3 2
```python
import random

top = scores[:k]
probs = softmax([s for _, s in top], temperature)
next_id = random.choices(
    [i for i, _ in top], weights=probs)[0]
```
|||
**コードの読み方**

1. `scores[:k]`: 上位 `k` 件だけを残す
2. `softmax(..., temperature)`: 温度で割ってから、確率にする
3. `random.choices(..., weights=probs)`: 確率に比例して 1 つ選ぶ (第7回と同じ)
:::

| 操作 | 小さくする | 大きくする |
|---|---|---|
| 温度 | 上位へ強く偏る | 候補間の差が縮む |
| `k` | 安全な候補に絞る | 低確率の候補も残す |

## 生成は「予測・選択・連結」の反復
### ここまでの接続を確認する

```text
文字列
  ↓ encode
トークンID のリスト
  ↓ next_scores
次の候補のスコア
  ↓ greedy または sampling
次のトークンID
  ↓ ids.append して繰り返す
長くなったID のリスト
  ↓ tok.decode
生成された文字列
```

途中の値を順に確認すれば生成結果だけを見るより原因を探しやすい

## モデルは会話を記憶せず履歴を毎回読み直す
### 4. 会話にする

```text
system: 簡潔に答えてください。
user:   日本の首都は？
assistant: 東京です。
user:   人口は？
assistant:
```

- 過去の発言と新しい質問をまとめてモデルへ渡す
- 履歴に前の回答があるため、「人口」が東京を指すと解釈できる
- 履歴を削れば、その情報を使えなくなる

「覚えている」ように見える動作は入力に履歴が含まれるために起こる

## 入力長と出力品質の限界
### 4. 会話にする

| 現象 | 理由 | 扱い方 |
|---|---|---|
| 会話が次第に遅くなる | 履歴が長くなる | 古い履歴を削る・要約する |
| 同じ表現を繰り返す | 選択が狭い | 温度や候補数を調整する |
| もっともらしく誤る | 次の語の予測器である | 事実を別の資料で確認する |
| 素朴なループが遅い | 毎回すべて再計算する | 実用では計算の使い回しを入れる |

0.8Bモデルは仕組みの観察には向くが実応用には向かない

## IDはモデルの中で変換されたベクトル
### 付録

```text
文字列 → トークンID → ベクトル → Transformer → スコア
```

- ベクトルは、各トークンを数値の並びで表したもの
- 注意機構は、前にあるトークンの情報を混ぜる
- 最後に、語彙中の各トークンへ1つずつスコアを出す

> 内部の数式より先に、入力と出力の形を押さえる

## top-pは確率分布に合わせて候補数を変える
### 付録

- 候補を確率の高い順に並べる
- 確率の合計が `p` に達するまで候補を残す
- 1つが突出すれば少数、拮抗すれば多数の候補が残る

```text
分布A: 0.80 0.10 0.05 ... → p=0.9 なら2候補
分布B: 0.25 0.20 0.18 ... → p=0.9 なら多くの候補
```

```python
probs = softmax([s for _, s in scores], temperature)

keep, cum = 0, 0.0
for prob in probs:
    if cum >= p:         # 足す前の合計が p に達していたら打ち切り
        break
    keep += 1
    cum += prob
# scores[:keep] が残った候補
```

`top-k` は候補数を固定し、`top-p` は確率の合計を固定する
