* 各回の狙い

** 第1回: 関数が値であること

基礎文法の説明はしない (付録に早見表を置いてある)。
「関数もただの値」という一点から、動的言語らしい書き方を3つ見せる。

- ディスパッチテーブル — =if= の連鎖を辞書ひとつに畳む。実行中に分岐を足せる
- デコレータ — =@deco= は =f = deco(f)= の糖衣構文にすぎない
- 登録デコレータ — 定義した瞬間に辞書へ登録し、文字列から関数を呼ぶ

山場は =@memo= の実演。竹内関数 =tarai(12, 6, 0)= の呼び出しが
*12,604,861 回から 225 回* に落ちる。関数の中身は1文字も変えていない。
課題の確認セルがこの回数を実際に assert する。

** 第2回: 数えて、選んで、つなげる

テキストを刻んで統計を取り、そこから文章を生成する (マルコフ連鎖)。
辞書とループだけで、確率的な文章生成が動く。温度パラメータまで実装させる。

後半はスタックと逆ポーランド電卓。第1回の登録デコレータを =@word= として
再利用し、=evaluate= が6行で書けることを見せる。

** 第3回A: 小さな言語モデル

第2回のマルコフ連鎖と骨格が一致していることから入る。

|              | 第2回                     | 第3回A                    |
|--------------+---------------------------+---------------------------|
| 次の語の予測 | =table[word]= を引く      | =model(文脈)= を呼ぶ      |
| 予測の中身   | 数えた回数の表            | 学習した重み              |
| 選び方       | =random.choices= + 温度   | サンプリング + 温度       |
| 生成         | 選んでつなげるループ      | 選んでつなげるループ      |

「表を引く」を「関数を呼ぶ」に差し替えるだけ、という筋で通してある。

** 第3回B: Forth

ユーザが実行中に語彙を増やせるようにする。そこで電卓が言語になる。

* デザイン

=assets/slides.css= に全スライド共通のテーマがある。

- フラットデザイン。角丸・影・グラデーションを使わない
- reveal.js 5.2.1 のテーマ変数 (=--r-*=) を上書きして配色を差し替え
- 配色: 紙 =#faf8f4= / 墨 =#14140f= / 朱 =#a02b0c= / 青緑 =#0a544c= / 黄土 =#6d5410=
- 書体: IBM Plex Sans JP + IBM Plex Mono (Google Fonts)
- 投影を前提に、本文 40px・線は 3px 以上・中間色は暗めに寄せてある

*アニメーションは使っていない。* =transition: 'none'= かつ =fragments: false=。
段階表示 (fragment) は入れないこと。

Bootstrap は使っていない。reveal.js が自前のレイアウト機構を持っていて、
グリッドとタイポグラフィが二重になって競合するため。

** スライドが枠に収まっているかの確認

キャンバスは 1200x700。はみ出すと投影時に切れる。
ブラウザのコンソールで確認できる。

#+begin_src js
document.querySelectorAll('.slides section:not(:has(section))').forEach(s => {
  Reveal.slide(...); // 各スライドへ移動して scrollHeight を測る
});
#+end_src
